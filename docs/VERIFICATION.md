- 经过两天、两轮放逐投票、15 段已提交 AI 公开发言，流式字幕共更新 2419 次。

- 对局后修正了复盘提示词，使其区分“当时可知的信息”和“终局已揭晓身份”；对同一已结束对局单独重新生成复盘成功。修改没有重跑或改变此前对局行动。

## 本地 TTS 实测

按用户要求，TTS 已切换为本机 CPU 上的 sherpa-onnx 2.0.0 + Kokoro v1.1-zh INT8。模型下载通过固定 SHA-256 校验，安装目录约 295 MiB；再次执行 `pnpm tts:setup` 成功复用模型。服务只监听 `127.0.0.1:8880`，推理不需要云端 Key。

- `pnpm tts:probe` 通过：八位 AI 与旁白共九种中文音色实际合成成功，输出均为 24 kHz、单声道、16 位 PCM WAV，所有样本波形均有非零音量。
- 同一句 31 字符中文样本生成 6.51–8.12 秒音频，本机合成耗时 4172–5728 ms；这组数字代表该短文本和本机 CPU，长发言会等待更久。
- 浏览器通过真实生产 `/api/tts` 重播当前对局中周予的 PK 发言，显示“正在配音”与周予高亮；缓存重播及关闭配音停止播放正常，浏览器控制台无 error/warn。验收后恢复原有静音偏好。
- 长发言每段不超过 300 字符，播放器已改为按 `X-Audio-Chunks` 顺序请求所有段落。服务端测试检查每段来自已提交文本、缓存复用、非法段号拒绝，以及 TTS 不修改对局状态；浏览器实测上述 PK 发言未跨多个段落。
- 生产构建与重启完成；运行中的 `/api/game` 返回 `tts=kokoro-v1.1-zh`，文本模型配置仍有效。原有三份对局及三份会话文件的 SHA-256 全部保持一致。

证据：[本地多音色与重启报告](evidence/local-tts.json)、[浏览器播放截图](screenshots/local-tts-playback.png)。实际 WAV 与完整报告保存在本机忽略目录 `.data/audit/`，可通过 `pnpm tts:probe` 重新生成。部署说明见 [LOCAL_TTS.md](LOCAL_TTS.md)。

## 本地 STT 实测

玩家语音识别默认改为本机 CPU 的 sherpa-onnx 2.0.0 + SenseVoiceSmall INT8。官方固定版本归档下载完成，经安装器固定 SHA-256 校验并解压；`pnpm stt:setup` 成功复用已安装模型和依赖。服务只监听 `127.0.0.1:8881`，无 STT Key 即可工作；本地出错不会自动上传到云端。

- 默认 `pnpm stt:probe` 使用模型附带的 16 kHz 中文公开样本：5.592 秒音频，本机一次识别耗时 261 ms。识别结果为“开饭时间早上9点至下午5点。”，原句“开放”误识别为“开饭”，报告保留参考文本和 `exactMatch=false`。probe 校验时间和数字关键内容，不表示逐字完全正确。
- 使用已运行的本地 Kokoro 合成 11.768 秒、24 kHz 的狼人杀样本，再真实调用本地 STT，识别耗时 311 ms。正确识别预言家、查验、五号、放逐等内容，“金水”误识别为“精谁”。这些耗时只代表当前机器和两条样本，不是一般性能或准确率承诺。
- Chrome 文件虚拟麦克风验证了真实 `getUserMedia → AudioWorklet → PCM WAV → /api/stt → 本地模型 → 草稿`。原草稿得以保留并追加转写；识别本身没有改变游戏版本和事件，玩家编辑后点击「结束发言」才提交文字。
- 浏览器检查通过麦克风拒绝、录音取消、延迟转写取消、迟到结果丢弃；模拟首个 AudioWorklet 初始化延迟并取消后，新录音仍正常。自动停止上传的 WAV 为 29.504 秒，真实转写成功。390 像素时录音和提交按钮保持在视口内，页面宽度为 390。无页面脚本错误。
- 生产构建后使用独立 `next start` 进程，再通过真实会话上传公开中文 WAV；`/api/stt` 返回 HTTP 200 与转写文本，游戏状态保持一致。
- 应用测试补充 local/external/zhipu 提供方协议、STT 专用 Key、loopback 限制、响应体上限、空结果/错误处理、取消，以及服务端对局/回合失效后的拒绝。转写接口响应为 `private, no-store`。

实际报告见 [local-stt.json](evidence/local-stt.json)，截图见 [桌面草稿](screenshots/local-stt-draft.png)、[移动端草稿](screenshots/local-stt-mobile.png)。模型和完整本地验收产物保存在忽略的 `.data/`，部署和外部 API 配置见 [LOCAL_STT.md](LOCAL_STT.md)。

验证边界：浏览器使用固定音频作为虚拟麦克风，没有对用户的物理麦克风、真实环境噪声或口音进行测试。外部 STT 适配器使用固定响应测试验证，没有调用付费云端识别，也没有因本次改动重跑真实 AI 完整对局。识别结果需要玩家校对；本地 SenseVoice 不支持本项目动态术语 prompt。

历史云端 `glm-tts` 探测曾返回 HTTP 429／错误码 `1113`，现已由本地 TTS 替换；历史记录保留在 [provider-probe.json](evidence/provider-probe.json)。`node scripts/provider-probe.mjs` 是显式的智谱识别探测工具，仍通过 stdin 接收 Key，不代表游戏默认使用云端 STT。

## PR #3 审查修复验证

合并前复查修复了三处问题：无 Content-Length 的 multipart 请求在解析前缺少实际流量上限；临时识别失败后丢失唯一录音；长草稿追加转写时静默截断。修复后：

- 上传按实际读取字节限制到 26 MiB，超出返回 413 并取消源流；新增回归覆盖缺失和伪造 Content-Length，均不调用模型。真实 HTTP 32 MiB 分块上传同样返回 413，游戏状态不变。
- 浏览器模拟一次服务忙后，点击「重试转写」成功调用真实本地模型。两次上传的 WAV SHA-256 相同，只打开一次麦克风；成功、取消待重试、取消正在重试时均释放重试入口，迟到结果不进入草稿。
- 1190 字原草稿追加实际转写后保留全部 1205 字，显示超长提示并禁止提交；玩家删减后恢复提交。确认前游戏状态不变，确认后只提交玩家编辑的正文。
- 390 像素视口中，重试、取消、录音和提交控件均在视口内；控件可换行，按钮文字不会被压成多行。浏览器无 pageerror。
- 初次审查修复通过 49 项应用测试；随后同步最新 main（a14fbb5，含 PR #4 界面改进），处理 GameApp 状态、偏好和操作区冲突。组合版本重新通过 typecheck、56 项应用测试、6 项本地 STT 测试、5 项本地 TTS 测试、生产 build 和 diff 检查，包含原有 250 局回放及 7 项界面逻辑测试。
- 组合版本重跑同一 WAV 重试、1205 字完整草稿、编辑提交、390 像素界面、字号切换与手记抽屉，均正常；麦克风拒绝、旧初始化取消隔离和自动停止也重跑通过，上传 WAV 时长为 29.512 秒。

证据：[审查回归报告](evidence/local-stt-review.json)、[手机重试](screenshots/local-stt-review-retry-mobile.png)、[超长草稿](screenshots/local-stt-review-overflow.png)。录音来自固定音频虚拟麦克风；临时失败由验收脚本注入，重试路径调用真实本地模型，未测试物理麦克风和付费外部识别。

## 浏览器检查中修复的问题

- Next.js 将请求 URL 主机规范化为 localhost，导致 127.0.0.1 来源被误拒。现在根据实际 Host 与协议检查同源，并测试跨主机、跨端口和跨协议请求仍被拒绝。
- React 开发模式首次效果执行覆盖了保存的静音偏好。现在读完本地偏好后才允许持久化，刷新后保持关闭配音。
- 字幕原先可能把上一位 AI 的正文标注成当前等待发言的真人。现在姓名、头像、正文和高亮使用同一条发言或配音事件。
- 窄屏图标操作补全可访问名称；没有发言席位的狼队结论按系统记录显示，避免出现 undefined 玩家。
