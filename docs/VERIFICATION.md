## 真实文本模型整局

通过实际 HTTP 接口调用 `glm-5.3-flash`，完成一局真人村民＋八名 AI 的对局。真人操作由验收脚本根据可见视图提交，没有读取隐藏身份来决定行动。

- 经过两天、两轮放逐投票、15 段已提交 AI 公开发言，流式字幕共更新 2419 次。
- 第一日被放逐猎人完成遗言及开枪，第二日最后存活神职出局后，按屠边规则判定狼人获胜。
- 完整对局约耗时 168.8 秒，包含真实模型发言、技能、投票和初次复盘。
- 验收脚本同时检查真人视图的隐藏身份、狼队私聊隔离、事件 ID 唯一性、重复提交幂等及终局刷新恢复。
- 对局后修正了复盘提示词，使其区分“当时可知的信息”和“终局已揭晓身份”；对同一已结束对局单独重新生成复盘成功。修改没有重跑或改变此前对局行动。

公开终局及发言证据：[full-game.json](evidence/full-game.json)。该文件不包含 API Key 或会话 Cookie。

## 语音验收限制

真实 `glm-tts` 请求返回 HTTP 429、错误码 `1113`：“余额不足或无可用资源包”。用户已明确选择暂不充值，交付时注明语音未实测通过。

因此本次**没有完成真实角色配音播放、真实 GLM-ASR 转写及本机麦克风端到端验收**。配音队列、静音／重播、WAV 录音编码、可编辑草稿、服务端语音接口均已实现；WAV 校验及 ASR 协议使用固定服务响应验证，通过不代表真实语音服务可用。配音额度错误会停止自动队列，用户可以继续文字对局或手动重试。

真实接口探测证据：[provider-probe.json](evidence/provider-probe.json)。额度可用后，使用 `node scripts/provider-probe.mjs` 通过隐藏的 stdin 重新探测即可。

## 浏览器检查中修复的问题

- Next.js 将请求 URL 主机规范化为 localhost，导致 127.0.0.1 来源被误拒。现在根据实际 Host 与协议检查同源，并测试跨主机、跨端口和跨协议请求仍被拒绝。
- React 开发模式首次效果执行覆盖了保存的静音偏好。现在读完本地偏好后才允许持久化，刷新后保持关闭配音。
- 字幕原先可能把上一位 AI 的正文标注成当前等待发言的真人。现在姓名、头像、正文和高亮使用同一条发言或配音事件。
- 窄屏图标操作补全可访问名称；没有发言席位的狼队结论按系统记录显示，避免出现 undefined 玩家。
